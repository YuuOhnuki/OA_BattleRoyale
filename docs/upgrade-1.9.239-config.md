# 設定と管理操作

## 奈落判定

プラグインの `config.yml` に次を指定し、サーバーを再起動する。項目がない場合も既定の-10を使う。

```yaml
void-death:
  y: -10
  maps: {}
```

マップごとの指定例：`maps: {sky: -8, end: -12}`。キーは `br / nether / cave / sky / end`。省略したマップは `y` に従う。5会場の登録床はY=40以上、天空島/エンドの平らな島面はY=80なので、既定値は全て-10とした。既存のY=0救済より下にあり、救済後も復帰できなかった人を死亡にする。設定を0より上にすると先に即死し、既存救済は使えなくなる。

対象は試合進行中・生存参加中・5会場内のプレイヤー。観戦・練習・ロビーは対象外。耐性やトーテムを経由せず死亡し、既存の死亡/観戦/キルログへ進む。通常の体力や防具の値を変えない。

## 天空島の選択と再生成

ロビーの5ボタン、プレイヤーメニューの天空島選択で、ホスト/管理者だけに60秒有効の確認が出る。確認は本人と一回限りのトークンに結び付く。

- 「既存マップを使用」は完成済み会場だけを選ぶ。生成を開始しない。
- 「再生成する」は、完成済み会場を先に新しい保存世代へバックアップし、成功後に生成する。手編集は新しい地形で上書きされるが、バックアップから戻せる。
- 未生成のときは既存会場を選べず、生成を案内する。
- 試合中・生成中・保存/復元中・手編集ロック中には開始しない。連打や別人の確認では二重生成しない。
- 旧来の試合後自動再生成は、`map-reroll.automatic-after-match: true` を明示した場合だけ動く。既定は選択時の確認に統一。

生成中は既存ボスバー、選択UIは未生成/生成中/停止中/生成失敗/完成を区別する。テンプレート配置失敗は完成にしない。完成するまでは固定見本。完成後の地図は上空のガラスを透過した実地形を使う。バニラのitem_displayは地図のピクセルを描けないため、実地図部分は壁中央の3×3固定額縁で表示する。未完成時の見本は従来のリソースパックの大きなパネル。安全用のガラスの当たり判定は維持する。

## 小島の生成設定

`scripts/map_islands.json` が生成時の正本。変更後は生成スクリプトと静的/複数シード検査を実行して配布する。サーバー上で毎tick JSONを読まない。

|項目|意味/制限|
|---|---|
|name|地点名と抽選結果に使う表示名|
|weight|出現抽選の重み、1〜20。天空島は重み付き・同種類重複なし。エンドは各スロットの3候補間の重みに利用|
|radius|天空島は半径16〜25。エンドは16〜30の構造配置範囲（橋の接続を保つため島の固定土台そのものは縮めない）|
|structure|同じマップの登録済み構造キー。別の種類の構造を利用可能|
|chests|5〜12個。通常/特別の合計。既定7|
|chest_positions|空配列なら従来の構造/地形に合わせて自動配置。指定する場合はchestsと同じ個数|

`chest_positions` の要素例は `{"x": 3,"y": 1,"z": -4,"rich": false,"facing":"north"}`。X/Zは島の中心からの相対座標、Yは島の基準面（絶対Y=80）から。配置範囲外は生成を失敗にする。到達不能・頭上が塞がる場合は検査で修正されるので、最終位置は `MAP_SKY_QUALITY.json / MAP_END_QUALITY.json` で確認する。

島の土台・橋・救済足場32個は既存座標を維持する。大きな地形・新構造・鉱石増量を既存の本番会場へ勝手に適用しない。適用には再生成が必要。

## 手編集と世代保存

権限は既存の `oa.plugin.admin`。`/oaplugin map` に統一し、従来の対象を指定する方式も維持する。

```text
/oaplugin map edit
/oaplugin map info
/oaplugin map save
/oaplugin map backup
/oaplugin map history
/oaplugin map load
/oaplugin map reload
/oaplugin map end
```

引数を省略した場合は現在いるBR会場を判定し、対象名を表示してから操作する。ロビー・練習場・他ワールドでは省略保存しない。ロビーを保存するときは従来通り `save lobby` と明示する。

`edit` は試合/通常生成をロックする。`save` または `backup` は新しい世代として保存し、過去世代を残す。従来との互換性のため、保存後の次回生成はその保存版を使用する。`end` は編集ロックを解除するだけで自動保存はしない。再起動後もロックが残ったときは管理者が `end` で解除する。保存中は編集を止め、完了メッセージを待つ。

`load sky <保存版ID>` のように履歴の世代を指定して復元できる。ロードは指定範囲の現在のブロック/登録目印を上書きするため、必要な現在の編集は先にbackupする。保存対象はブロック・展示・登録目印・地点名・砲撃の柱・開始地点など。プレイヤーの持ち物や戦績は保存しない。実地図の一時額縁は保存せず、復元後に描画し直す。

## 新地形を適用する管理者の手順

コード更新だけでは既存会場を書き換えない。天空島はロビーで選択して「再生成する」を使えば、全体バックアップ→標準生成への切替→再生成まで行う。

エンド・地下などをコマンドで更新する場合は、次の順に実行し、**バックアップの完了を待つ**。

```text
/oaplugin map backup end
/oaplugin map use end generated
/function oa:map/rebuild_end
```

地下はそれぞれ `backup cave`、`use cave generated`、`/function oa:map/rebuild_cave`。天空島を手動で行う場合も `backup sky`、`use sky generated`、`/function oa:map/rebuild_sky`。

`backup` の後に `use <key> generated` を省くと、互換機能により次の生成はバックアップした保存版を復元するため、新地形にならない。標準生成への切替は履歴を削除しない。再生成は現在の手編集を上書きするので、必要な内容は保存履歴から復元する。別会場の復元/生成に進む前に編集モードは `end` で終了する。

## 砲撃と動物

砲撃はユーザー確認により、開始後10秒経過ごとに待機を2.5→2.0→1.5→1.0秒へ短縮する。予告1.2秒は別に固定なので、実際の照準開始間隔は3.7→3.2→2.7→2.2秒。ダメージ4HP・半径2m・地形破壊なしは維持。

ブタは2列×6行の軌跡を共有し、3〜5秒ごとに方向を選ぶ。誰かの足場が壁/奈落に当たると全体を止めて別方向へ。各ブタの爆発は0.5秒ごと、被害者側は従来通り2秒に一度・2HP。ニワトリは0.5秒ごとに経路を調整し、3〜7mを保とうとする。通常Mob AIの経路探索が通れない地形で必ず追従できることまでは保証しない。
